# Maintain the Optimizely migration knowledge

Use this outside the client runtime to prepare a versioned knowledge bundle. It does not require another runtime agent. The client team remains Orchestrator, Developer and QA. A maintenance task can be assigned to an available qualified agent with actual file/source capabilities.

Read the [authoring procedure](references/authoring.md), [coverage rubric](references/coverage-rubric.md) and [scenario evaluations](references/evaluations.md). Skills should support correct implementation decisions, not just contain a topic list. Preserve useful domain depth while keeping short entrypoints and focused references that load on demand.

Separate platform concepts, project decisions, REST definitions, SDK declarations and Graph responses. Mark each example conceptual, documentation-checked, compiled or tenant-tested; use only the strongest status established by evidence. A documentation lookup is not a successful integration. Record exact source, checked date, supported version and conflicts.

For new projects qualify the official published SDK/template path; for existing projects follow the installed family. Do not combine moving main-branch SDK examples, retired APIs and an older starter. Recheck source-specific defaults and tenant capabilities before asserting them.

Identify the canonical portable source and the intended installed copy before editing. Version and validate the source, package it, then update an installed Kajoo copy only when requested and authorized. Use actual available skill APIs and schema, batch supporting-file writes where supported, and read back every saved representation. Local changes alone do not update Kajoo or a remote recipe catalog.

Return changed references, affected implementation decisions, source ledger, old/new evaluation results and remaining integration checks. Keep client screenshots, credentials and task-specific identities out of reusable skills. Model decisions affecting an active migration return to Orchestrator with the affected revision identified.

For recipe 1.5.0, keep all entry instructions consistent with the five-phase operation contract and four roles. Validate documentation-only Phase 2, empty-until-approved Phase 3, dynamic task idempotency, readable field/reuse tables, shared render-path parity, significant user-approval batches and failed-preview download behavior. Test generic scenarios from multiple website domains. Scan bundled AGENTS.md as well as skills for conflicting instructions; a runtime template overlay is part of the agent context. No automatic deployment follows package generation.
