# Shared rendering, preview and download fallback

Developer implements the same semantic components, site layout, fonts, tokens, assets and layout wrappers for delivery and CMS preview. Fixture adapters may supply representative data through those renderers; a mock-only route must not be the only location of required CSS, shared header/footer or content. Optimizely Specialist configures the application/root/host and QA tests the integration.

Qualification checks:
- Confirm the Kajoo URL is reachable by the editor's browser, stable for the review session, uses the required scheme and retains access controls. Test iframe embedding and tenant-specific CSP/communication script compatibility. Do not globally disable security headers to pass a test.
- Configure the approved application host and preview URL/context/version/locale mapping. This is an external change requiring approval. Use the installed SDK's qualified preview helper, or the documented equivalent. Keep preview tokens out of logs, screenshots, public bundles and generated Markdown.
- Retrieve unpublished content with the current preview token and correct locale/version; do not rely on public delivery credentials for drafts. Avoid shared caching of private preview responses. The official documentation describes short-lived preview tokens; never persist them as configuration.
- Verify composition node identity and field overlays using actual returned identities and installed helper semantics. Check section/row/column/element selections, field edits, refresh after change and published-mode behavior. Overlays appear only in edit context; do not remove required composition-node metadata while adding field attributes.
- Fetch shared layout content consistently; verify no duplicate header/footer, correct default/override and draft/public visibility. Test without fixture values masking absent CMS data.
- Compare source, delivery and CMS rendered page area at equivalent viewport/content/state/locale/font conditions. Editor controls are excluded. Record measurable differences and accepted tolerances; never claim pixel identity from a build alone.

If Kajoo preview fails, record the failing check and bounded diagnostic result. Pause dependent CMS preview acceptance/release; continue independent document or local fixes. Developer provides a downloadable runnable archive through Kajoo evidence/file export:
1. Include source, required public assets, configuration templates, package manifest/lockfile, safe startup instructions and exact runtime/package-manager versions. Include a file inventory and checksum.
2. Exclude .env values, access/preview tokens, credentials, private logs, .git, node_modules and build caches. Keep a blank .env.example. Inspect archive contents and validate extraction/install/type/build where feasible; explicitly report unrun checks.
3. Provide local setup, env-variable purposes and secure credential entry, local host/port and exact preview route. Explain the separate user-approved Optimizely application hostname/preview setup for that local host. No credentials embedded in URLs.
4. Offer the actual downloadable artifact, not a path that only exists inside the agent sandbox. Ask the user to run it and return local CMS-connection evidence when the platform cannot do so. Document pending checks; export success is not CMS preview success.
5. Resume from the saved state once preview evidence exists. Do not restart discovery or model preparation.

Hosting deployment for a stable preview still requires a concrete user-approved batch. An existing authorized Kajoo local preview process may be reused without publishing or exposing a new public host.

## Shared rendering and integration qualification
Phase 3 implements CMS-ready models, placement configuration, media dependencies, registered renderers, delivery adapters and preview plumbing as well as visual UI. Local qualification is not proof of tenant/editor acceptance. Use typed, qualified Graph/SDK response shapes or sanitized real responses for contract fixtures; label assumptions. Exercise nested URLs/link labels, media references/binary URL resolution, missing values, display settings and shared content through production adapters. Do not claim exact tenant shape can only be considered after deployment.
Fixture and CMS paths use the same components/styles and normalized rendering model; transport adapters may differ. Place fixtures on an explicit test-only route so a static page cannot shadow the CMS canonical route. Keep production routes derived from the project brief. Propagate authorized draft/version/locale context to shared header/footer and related fetches; prevent shared draft caching. Invalid/expired preview authorization produces a clear diagnostic, never a silent published-only fallback that hides shared drafts. Do not expose tokens in logs/evidence.
After approved schema/assets, Task 4.4 qualifies one representative draft with section selection, media, link and shared chrome using existing appropriate content or a separately approved minimal bootstrap batch. Read back actual responses, reconcile adapters and verify the native CMS iframe edit/refresh path before broad composition in 4.5. This is not implicit permission for extra tenant writes or publication. Register the actual preview host via an approved batch and verify readback; ephemeral hosts require requalification if changed. Empty content and HTTP 200 are not proof. Preserve downloadable local fallback on unavailable Kajoo preview.
Task 4.5 composes remaining approved content only after qualification. Task 5.1 independently compares the actual CMS-driven page to source and verifies picker selection, edits, refresh, references/images and shared regions. Test published delivery separately after its approval. Late code fixes remain possible but must identify the violated contract, update affected evidence and be manually started as implementation tasks; do not disguise planned missing integration as normal styling work.
