# Repeatable comparison
Use existing website-visual-qa capture tooling in the same source session, scoped to actual component parts. For fidelity work enable selective styles; record exact visible text and asset/font inventory alongside it. The current capture helper does not fully qualify CSS backgrounds, actual rendered fonts, pseudo-elements, clipping or every state. Use bounded targeted Playwright inspection for those gaps; never mistake helper success for complete coverage.
Capture source and target in the same browser environment, viewport/DPR, locale, consent, scroll and interaction state. Wait for fonts and relevant images; stabilize animations. Store immutable originals and coordinates. Compare the CMS rendered page area excluding editor chrome without masking actual site differences.
Run `node scripts/compare-images.mjs source.png target.png output-directory` with the installed sharp dependency. It writes a side-by-side image, overlay, amplified RGB difference image and JSON with hashes/dimensions/raw metrics. It pads unequal images on the right/bottom, never stretches them; alignment differences remain visible. Missing pixels count as changed. Metrics are diagnostic only and never auto-pass visual QA. Antialiasing and dynamic content require agreed tolerances and explicit scoped exclusions, not arbitrary threshold increases. Do not overwrite the source baseline with target output.
Review each visual contract checkpoint and record measured expected/actual/delta plus screenshots, code revision and exceptions. Confirm painted visibility, font wrapping, decoded images and semantic order as well as boxes. Reuse the result for the same code/content/state; invalidate affected consumers after shared CSS/font/adapter changes.
Official reference: [Playwright visual comparisons](https://playwright.dev/docs/test-snapshots). Different OS/browser/font environments can produce differences; numerical similarity alone is not acceptance.
