# Bundled template setup — recipe 1.4.0

Use only for the assigned setup task. Later component implementation uses its compact handoff and prepared path; do not repeat setup.

1. Read repositoryMode and target from the brief. Default: bundled, `/workspace/repos/optimizely-nextjs-saas-template`. For explicit existing mode, reuse that exact directory and skip steps 2–4. Read its package manifest, lockfile and applicable repository instructions once; use its established package manager, frozen/immutable install command, supported local checks and actual model/registry source paths. Do not impose pnpm, next typegen, or bundled file locations on an existing project. Continue at step 5 with its actual results. The Code UI uses the sandbox repository root; never use the publisher's Windows path.
2. Locate this loaded skill's own directory from its tool-provided path. Run `node <skill-directory>/scripts/prepare-template.mjs --target <absolute-target>`. The helper reads the asset itself: do not display/read the 243 KB payload into the agent context. It preserves dotfiles and records original/bundled hashes and scope overlays in `.kajoo-template.json`. An existing unrecognized target is preserved and reported; do not delete it. If interrupted, report the partial target rather than overwriting it. An unchanged rerun with a receipt preserves user modifications.
3. In bundled mode use [pnpm bootstrap and recovery](pnpm-bootstrap.md). Run the shipped `scripts/ensure-pnpm.sh` once; it reuses pnpm 12.5.1 or installs that exact version with npm into an agent-writable tools prefix. Using npm to install this tool is allowed; using npm to install the application's dependencies or replace its lockfile is not. No sudo, global install, Corepack activation, SDK reading or dependency upgrades. Record the returned absolute executable path; do not rely on PATH changes surviving tool calls. Missing pnpm alone is recoverable, not a final blocker. If Node/npm, write permission, network or package verification prevents recovery, report that concrete blocker after one bounded attempt and retain successful extraction.
4. From the exact prepared repository, use the returned executable for `install --frozen-lockfile`, `exec next typegen`, `exec tsc --noEmit` and `run lint`. Follow the bootstrap guide's command pattern. Record real exit statuses and resume at the failed step rather than re-extracting or reinstalling unchanged successful steps. Build/preview may need font access or CMS data; neither authorizes opti-push. Record SDK/CLI from package/lockfile once (bundled resolved versions: 2.2.0); no routine node_modules inspection. The beta validator is partial coverage, not SDK 2.2.0 certification.
5. Save a compact receipt under evidence: exact target, bundle digest, recipe version, Node/pnpm versions, exact pnpm executable/tool prefix and bootstrap result, SDK/CLI resolved versions, lockfile hash, commands/results and remaining blockers. Feed the prepared path and existing `src/components/Page.tsx` / `src/app/layout.tsx` patterns to Phase 2. Copy a verified minimal pattern into each component handoff, not the entire repository. Preserve user changes on every retry and reuse unchanged successful checks.

The source template's README/AGENTS and Page comment have explicit demo-scope overlays. All other source bytes are preserved. Credentials, Git history, dependencies and build output are excluded. The original template was not modified. Default routes query CMS; local representative data/rendering is implementation work, not provided by extraction. No install, login, synchronization or application code execution occurs merely by applying the recipe to a workspace; Task 1.2 performs preparation when started.
